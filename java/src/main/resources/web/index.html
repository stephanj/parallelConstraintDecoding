    How the parallel engine fills a schema in a couple of passes
    
          
      
        1. Prefill once. The same prompt the baseline gets — schema, descriptions, allowed values, and the text — goes through the model a single time and stays in the KV cache.
          2. 
      
        2. Broadcast. That cached prefix is tagged for one sequence per field — no copying.
          3. 
      
        3. One batched pass. Every sequence gets its own "field": " suffix; the logits at each suffix's last token are read in the same forward pass.
          4. 
      
        4. Score only the allowed values. Softmax over the candidate tokens gives a calibrated probability per choice — nothing outside the schema can win.
          5. 
      
        5. Resolve ties level by level. Choices that share a first token are separated with one more batched pass per level, never one pass per token.
          6. 
      
        6. Assemble. The JSON is built from the winners, so it is always valid and never misses a key.

          Every falling piece is one extraction call: the board is the input, the legal placements are the
      allowed values of a single field, and the decoder picks one in two forward passes. At temperature 0 it takes the
      most probable placement; higher values sample from the distribution. With all legal placements offered, a small
      model mostly stacks on the left; offering only the heuristic's top candidates keeps the game going while the model
      still makes every pick.

        What the model is asked
        
            The prompt is the board as a 10×20 grid of #/., the column heights, the falling
          and next piece, and one line per legal placement stating what it would do (lines cleared, new holes, resulting
          height, bumpiness). The schema has one field, placement, whose allowed values are exactly those
          placements — so an illegal move is impossible. A small model is a weak spatial reasoner: the interesting part is
          watching it decide many times per second with a calibrated probability per option, not whether it beats the
          simple heuristic shown for reference.
